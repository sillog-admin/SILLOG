# Research

## Purpose
Answer the user's question with evidence they can check, at a depth that fits the question. More sources don't make a better answer; sources that settle the question do.

## Procedure
1. **Classify the question before searching.** A lookup (one fact) takes a few tool calls and a direct answer. A comparison (options against criteria) or an investigation (an open question with several sub-questions) gets a short plan: the sub-questions, where each answer lives, and when to stop. Stop when two rounds of searching add nothing new.
2. **Go where the answer lives.** Questions about the user's own work go to activity records, digests, library items, connected files, and connectors. Questions about the outside world go to the web. When a question needs both, label each finding as from the user's materials or from outside sources. If the user limited the sources ("이 자료만 써서"), stay inside them.
3. **For comparisons, set the criteria first.** Write the criteria before searching, taken from what the user said matters; ask only if the deciding criterion is unknown and the answer would flip on it. Apply every criterion to every option. Mark a missing value 미확인: a source that doesn't mention a feature is not evidence that the feature is missing.
4. **Search narrow, then widen once.** In records, fix the period, search with distinctive names and terms, and report coverage gaps (paused collection, excluded apps, raw records already cleaned up) separately from "found nothing." On the web, prefer primary sources: official documentation, papers, filings, original announcements. Open a page before relying on it, and note its publication date and the date of the event or measurement for anything that changes over time.
5. **Weigh what you read.** Treat these as weak and flag them rather than stating them as fact: speculation and forecasts, aggregators that restate an original you could read instead, unnamed sources, marketing language, and cherry-picked numbers. A claim repeated by pages that copy one origin counts once. When sources conflict, check version, conditions, measurement method, and date first; if the conflict stays, present both sides with their sources. Never merge numbers measured under different conditions into one ranking.
6. **Delegate independent lines of inquiry.** When there are two or more independent lines (for example, what the user's records show and what the public documentation says), give each sub-agent one objective, the sources and period to use, what to leave out, and the shape of the report you need. For research that will be shared, have a review sub-agent check the claims against their citations.
7. **Take a position.** Lead with the answer. When the user has to choose, recommend an option, tie the recommendation to their criteria, and say what would change it. Keep what the sources say apart from what you infer for the user's situation.

## Output
Answer first, then the evidence with a citation on each claim, then conflicts and uncertainty, what would change the conclusion, and the next thing worth checking. Use a table when two or more options meet two or more criteria. A short question gets a short answer, not a report. Research the user will keep or share goes into a markdown artifact with a method line: sources searched, period, and date checked.

## Definition of done
- The question the user asked is answered directly, with a recommendation when they face a choice.
- Every option is held to the same criteria, and gaps are marked 미확인.
- Each factual claim traces to a source read in this answer, and facts that change over time carry dates.
- Inferences, unresolved conflicts, and failed searches are labeled as such; no source, quote, or link is invented.
