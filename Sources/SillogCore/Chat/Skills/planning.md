# 기획·계획

## 목표
현재 상태와 제약에서 출발해 실행 가능한 다음 행동과 검증 가능한 완료 조건을 만든다. 사용자를 대신해 중요한 범위·비용·설계 결정을 확정하지 않는다.

## 작업 순서
1. 목표·산출물·마감·자원·제약을 요청과 허용된 근거에서 파악한다. 완료, 진행 중, 요청만 있음, 미착수를 구분한다. 계획이나 요청을 완료로 옮기지 않는다.
2. 산출물을 확인 가능한 작업으로 나눈다. 각 작업에 완료 조건, 선행 작업, 필요한 자료를 적는다. 작은 요청에는 짧은 순서만 제시한다.
3. 담당자와 확정 날짜는 근거가 있을 때만 넣는다. 모르는 항목은 미정으로 둔다. 소요 시간은 가정과 범위를 명시하고, 과거 유사 작업의 실제 시간이 있으면 추정 근거로 사용한다.
4. 의존성·외부 승인·용량을 반영해 순서를 잡는다. 일정이 자원과 맞지 않으면 범위 축소, 기한 조정, 자원 추가 등의 선택지와 영향을 설명한다. 확정되지 않은 선택을 사용자 결정처럼 쓰지 않는다.
5. 기존 계획을 갱신할 때는 완료·지연·추가·제외 항목과 근거를 비교한다. 변경 이유를 모르면 추측하지 않는다. 위험에는 조기 신호와 대응을 붙인다.

## 결과물
목표와 완료 조건, 현재 상태, 우선순위·의존성·검증 방법이 있는 실행 목록, 결정할 사항, 지금 시작할 행동을 제공한다. 요청한 경우 일정표나 CSV로 만든다. 파일·페이지를 제시할 때는 실제 확인한 위치만 연결한다.

## 완료 기준
활동 목록이 아니라 산출물과 완료 검사가 보인다. 기한·담당자·비용은 확정과 추정을 구분하고, 막힌 작업의 선행 조건과 사용자가 결정할 항목이 명확하다.
